The efficiency stack: bytes per token, lever by lever

Try this

  1. Defaults: Course-8B (8.03 billion parameters) on one H100 (3.35 TB/s), batch size 1, bf16 weights, short context. Switch weights to NVFP4 (NVIDIA's 4-bit floating-point format, 4.5 bits per weight with scales).
  2. Turn on drafting with draft length γ = 3 and acceptance rate α = 0.8.
  3. Raise the context to 131,072 tokens, then turn on the hybrid (4 of 32 layers keep attention).

What to notice

Each lever divides one term of the bytes read per token. Fewer bits shrink the weight term, drafting spreads one weight read over several tokens, and the hybrid shrinks the cache term. At long context the cache, not the weights, dominates, so the architecture lever beats the precision lever: NVFP4 plus drafting falls to about 430 tokens per second at 131,072 tokens, and the hybrid brings it back to about 1,230.
Model (as in 8.6). Decode at batch size 1 is memory-bound (1.3): time per full-model pass = bytes read / 3.35 TB/s. N = 8.03 billion parameters; bw = bytes per weight; skv = 131,072 bytes of KV cache per token in bf16 for Course-8B (2 × 32 layers × 8 KV heads × 128 dimensions × 2 bytes), halved for FP8 and divided by 8 for the hybrid. With drafting, τ = (1 − αγ+1) / (1 − α) tokens per round (from 6.6), and round time = γ × drafter cost × tw + tw + T·skv / bandwidth. Without drafting, τ = 1 and round time = tw + T·skv / bandwidth.
