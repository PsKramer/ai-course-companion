Parallelism planner: memory, traffic and step time per GPU

Try this

  1. Defaults: Course-8B (8.03 billion parameters, 8,192-token sequences) on 512 H100s with hybrid sharded data parallel (HSDP: shard within each 8-GPU node, replicate across nodes). Switch HSDP to plain distributed data parallel (DDP) and watch memory pass the 80 GB line.
  2. Set tensor parallelism (TP) to 8 with ZeRO-1, then turn on "TP across nodes".
  3. Set TP 2, pipeline parallelism (PP) 4 with ZeRO-1, then raise the global batch from 512 to 2,048 sequences (8 → 32 micro-batches): the bubble falls from 27% to 9%.
Model (Course-8B by default)

What to notice

Every axis trades memory for a different kind of communication. Sharding (ZeRO, FSDP) cuts state but adds gradient and weight traffic. Tensor parallelism cuts both state and activations, but its traffic only fits inside NVLink: across nodes it is 9× slower. Pipelines shrink memory cheaply, but they need many micro-batches to hide the bubble.
Model (same formulas as Exercise 4.5.1, from 4.4 and 4.5). dp = GPUs / (TP·PP); P = N / (TP·PP) parameters per rank. Training state in bytes: DDP 16P; ZeRO-1 4P + 12P/dp; ZeRO-2 2P + 14P/dp; fully sharded data parallel (FSDP) 16P/dp; HSDP 16P/8. Activations = (6d + 2·h_kv·d_h + 3·d_ff)·2 bytes per token per layer (full recompute: 2d bytes), ÷ TP, × L/PP layers × T × micro-batch × in-flight micro-batches (PP for 1F1B). Ring all-reduce sends 2(n − 1)/n·S bytes per GPU. Bubble = (PP − 1)/(m + PP − 1) with m micro-batches. Compute = 6N·tokens / (GPUs × 989 TFLOP/s × 40% model FLOPs utilization (MFU)); NVLink 450 GB/s, InfiniBand 50 GB/s per GPU. Step ≈ max(compute / (1 − bubble), NVLink time, InfiniBand time), assuming no overlap credit.
