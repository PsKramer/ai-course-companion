Speculative decoding: when does it pay?

Try this

  1. Defaults: Course-8B (8.03 billion parameters, bf16, 131,072 bytes of key-value (KV) cache per token) on one H100 with a 1.5 GB drafter, draft length γ = 4, batch size B = 1. Drag the acceptance rate α from 0.5 to 0.9.
  2. Set context T = 128 tokens and raise B to 128: the speedup falls below 1.
  3. Switch T back to 4,096 tokens and watch the crossover move right.

What to notice

Speculation turns idle compute into tokens. At small batch the verify step costs the same as a normal step, because both are paid in bytes read, so every accepted token is nearly free. As B grows, verifying γ + 1 positions per sequence makes the step compute-bound and the gain turns into a loss. Longer context keeps the step memory-bound longer, so the crossover moves right.
Model (as in 6.6). Bytes per step = 2N (bf16 weights) + B·T·131,072 (KV cache). Normal step = max(bytes / bandwidth, 2N·B / (efficiency·peak)). Verify step = max(bytes / bandwidth, 2N·B·(γ + 1) / (efficiency·peak)); the drafted tokens' own KV entries are ignored. Draft time = γ·drafter bytes / bandwidth. Throughput = B / normal step without speculation and B·τ / (verify + draft) with it, where τ is the expected tokens per target pass.
